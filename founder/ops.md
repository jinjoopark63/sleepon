## 5. 핵심 루틴 (첫날 보고 따라 할 수 있게)

**① 아침 점검 (15분)**
1. Crashlytics에서 지난 밤 크래시 수 확인 (전날보다 2배 이상이면 원인부터)
2. "밤새 재생이 중간에 멈춤" 비율 확인 (기종별)
3. "잘못 다시 켜짐" 신고 수 확인 → 3건 이상이면 해당 기종의 뒤척임 감지 기준을 보수적으로
4. RevenueCat에서 체험 시작, 결제, 해지, 환불 숫자 기록
5. 이상이 있으면 그날 첫 작업으로 등록

**② 업데이트 배포 (매주 금요일)**
1. 변경 사항을 테스트 기기 4대(아이폰 2, 갤럭시 2) 이상에서 **화면 끈 채 밤새 재생** 시험
2. 기본 모드 전환(연결 끊김) 확인
3. 스토어 제출 → 단계적 배포(안드로이드 10% → 100%)
4. 업데이트 노트는 `brand.md` 말투로 짧게

**③ 불만 대응 (24시간 안)**
1. 먼저 사과하고, 무엇이 일어났는지 그날 기록으로 확인
2. 바로 할 수 있는 방법 안내 (예: "버튼으로만 이어 듣기"로 전환)
3. 환불 요청이면 안드로이드는 직접 처리, 아이폰은 애플 요청 화면 링크 (약속한 대로)
4. 원인과 조치를 내부 기록에 남기고, 같은 불만이 3건이면 다음 배포에 반영
5. 리뷰 답글은 변명 없이 (`brand.md` 다섯 번째 접점)

**④ 주간 마감 (금요일 오후)**
1. 주간 숫자 3개 (`marketing.md`): 예약·체험 전환율, 획득 단가, 기관 파이프라인
2. 7일째 사용률, 14일 비교 결과에서 "차이 없음" 비율, 월간 해지율
3. 다음 주 할 일 3개만 정하기
4. 멘토 점검 때 공유할 한 장 업데이트

**⑤ 월간 정리 (매월 첫 주)**
1. 구독 매출과 스토어 정산 대조
2. 세무사에게 증빙 전달 (영수증, 스토어 정산서, 기관 세금계산서)
3. 서버·도구 사용량과 요금 확인, 쓰지 않는 도구 해지
4. 기관 시범 운영 보고서 (익명 통계만)
